02 · 什么要记录，什么要确认

保留原话→整理与核对→采纳待办 / 等待事项→明确确认日程→记录结果与下一步
对象／入口用来做什么需要你决定什么
记录方式 → 随口记 · 客户资料快速输入一段交流、复盘或客户资料。也可先用输入法语音输入，再核对文字。每次最多6000字。客户归属、事实和个人判断、具体行动；最后点“帮我整理”。
记录方式 → 手动新建记录手动建立“交流纪要 · 保留现场信息”或“待办事项 · 需要后续执行”。记录类型、客户、状态与内容；点“保存记录”。
客户交流围绕同一次交流，集中现场录音、我的复盘、后续补充。客户、实际发生时间、来源使用与逐项行动。不确定的实际时间可以留空。
录音与材料保存长文字、会议纪要、聆记转写；原文和历史版本可回看。客户、人物称呼、实际时间、专业词与行动依据。导入材料不要求先建客户。
客户与联系人企业基本资料、联系人和逐次累积的画像。AI提出的资料变更先“确认写入客户档案”；手动填写画像则明确选信息性质。
独立项目 / 商机同一客户的不同交易分别维护。项目金额与金额性质、审批、阶段、范围、采购路径、决策链、阻力、节点、联系人。
核对统一查看客户资料、行动与日程提案。采纳、不采纳、稍后处理、恢复；资料和日程分别确认。
跟进事项围绕一个持续目标，把推进动作、相关安排、沟通与材料一起看。旧资料在“查看原始记录”保留。这件事要达到什么结果、下一步做什么；有明确时间时再核对安排。
待落实安排把想到的未来活动留在同一处，逐步定日期、钟点和约定。先看当前缺口；确定安排的期限、下次推进点、实际活动时间分别记录。
日程查看已生效执行安排，以及有日期但仍需完善的计划。完整、明确的个人安排可直接落实；要求先核对或使用日程提案时再确认。未设置提前提醒也能建立日程；只有日期不猜钟点。
三类不同的决定写入客户档案决定资料；采纳为待办决定是否推进；安排日程决定具体执行时间。完整安排指令无需重复确认，AI建议或你要求先核对的方案仍需确认。日程没有提前提醒，不代表安排没生效。

原始记录和动作仍有“待整理”“跟进中”“已完成”；新版统一事项使用“跟进中”“等待反馈”“暂缓”“已结束”，它们表达的是整个目标的状态。项目阶段为“新线索”“已接触”“需求确认”“方案报价”“商务沟通”“已成交”“暂缓跟进”。阶段应按真实进展维护，不从金额或一句“有兴趣”推断成交。

本次更新 · 按目标持续推进

一件事，放在一处继续做

“准备好下次电力方案汇报”是一件事。重组 PPT、补充产品化内容是它的两个动作；和客户约一次汇报是相关日程；现场原话、项目材料和 AI 讨论是推进这件事的依据。你不必在几个列表中拼回同一个目标。

随口说一句→核对补入哪件事→在同一处补充、讨论→落实动作和时间→记结果，再决定目标是否结束
你要看什么在哪里看怎样继续
我在推进的事情工作台“我在跟进的事情”，或导航“跟进事项”每件事一张卡片，显示目标、下一步、动作完成数和最近安排；点标题或“继续这件事”。
具体需要做的步骤事项详情“待完成动作”；列表卡片“查看全部动作”点“查看 / 记结果”进入原动作。已完成动作收在折叠区，原始内容和结果继续保留。
什么时候去做事项详情“时间安排”；导航“日程”的日、周、月视角同一安排可从两个入口查看。日程按实际活动计算，不为每个准备动作复制一次会面。
之前说了什么、根据什么判断事项详情“沟通与进展历程”“原话与相关资料”展开回看原话、结果、客户交流、材料和讨论，再在上方继续告诉秘书。

只看某个项目正在推进的事

在总览 → 项目，点项目卡片的查看本项目的全部事项。列表和搜索只看当前项目；点“返回项目总览”回看其他项目，或用普通“跟进事项”导航回到全部范围。在项目事项里继续补充，新动作沿用该目标的明确项目。

项目卡片的已归组动作是统一目标下的动作进度；原项目行动明细默认折叠，用于回看原先直接关联项目的旧记录。两者口径不同，不能相加，也不代表完成几个准备动作就完成了整个项目。

新一句话怎样接到原来的事情

  1. 工作台直接输入，或打开具体事项，在“继续补充这件事”的输入框里说新进展。看清“正在补充”的事项名称；新目标先点另记一件事。
  2. 已配置模型时，秘书结合已有目标、客户和项目判断是续办、新事还是资料。回执显示已建立事项或已补入事项。只有客户相同、来源相同，不能证明是同一个目标。
  3. 有多个可能目标时，先保留原话，显示候选；点候选或这是另一件事，在“核对这句话归哪件事”里确认。不能确定客户、项目或步骤时，继续补充，不会替你猜一个执行时间。
  4. 只是资料、感受或客户背景时，可先保留为原话；不强行造一个待办。要落地时，回到目标说明“下一步我要做什么”，或在 AI 讨论中核对后采纳行动。
自动理解与正式执行分开看。

你明确说出的个人动作、已知步骤的新进展可以由秘书整理；模型推测的建议仍需采纳。录音里的承诺先核对来源与责任人，不能当作你在当前对话中下达的执行命令。缺少模型时使用保守规则，页面结果以实际配置和回执为准；本页例句不是外部模型效果保证。

归错、归组与拆分，都能先看影响

  • 一句话归错：在该条回执点“归错了”，选已有事项或“这是另一件事”，再点“确认归属”。这只调整本次原话、新建步骤和材料的关联，不重新运行 AI、不重做已完成步骤、不改原日程。已经记入旧步骤的进展仍留在原处；需要更正业务结果时，打开原动作核对。
  • 旧数据还没有归到事项：“跟进事项 → 核对历史归组 → 核对这次归组”。改成一个清楚的目标，勾选确实服务该目标的动作，再点“确认归成一件事”。原客户数据、原话和动作不会自动归组，打开建议也不会改变资料。候选没有覆盖的内容仍能从“查看原始记录”使用。
  • 本来是一件事，却分成了两件：打开其中一件，点“更多 → 归入另一件事”，选择同单位、同项目的保留事项，核对合并影响后确认。归出事项收起，原动作、原材料、原安排保留。
  • 本来是两个目标，却混在一件：“更多 → 拆出独立的事情”，只勾选独立目标的动作，写新名称和要达到的结果，先预览再确认。拆分后核对两个事项的时间安排；不要把共同的会面再建一次。
  • 想撤销关联变化：展开事项详情“归组与变更历史”，点“查看撤销影响”，核对后“确认撤销”。后续已有新修改时可能阻止撤销，以免覆盖新进展；此时先查看最新事项，原记录仍在。

确认有歧义的原话归属，不代表原先待核对的建议已经采纳。归属核对窗口不会再次生成动作；返回该事项继续说明要做的事，或核对原资料中的行动建议。

和 AI 讨论，再把建议加入同一件事

  1. 从事项详情点与 AI 讨论下一步。已知的单位和项目沿用该事项；没有客户时，先选择本次讨论针对的客户。
  2. 问具体的推进问题，例如“材料还缺什么证据，下一次汇报怎样让客户明确试点范围？”秘书参考当前目标、相关动作、资料和安排，建议与客户已确认事实分别保留。
  3. 点建议的采纳入口，核对标题、谁来推进和相关人，必要时修改材料或完成标志。采用后的动作留在该事项中；没有时间先留未排期待办，具体时间另行核对。
  4. 目标、资料或归属有新变化时，旧建议可能不能直接采用；结合新进展重新讨论。归档、回收站或已结束事项可以回看讨论，恢复或重新设为跟进中后再继续推进。

三种“完成”不要混在一起

完成了什么记录什么这件事接下来怎样
原话已经整理保留整理结果和来源不代表动作完成，更不代表目标达成。
PPT 或其他准备动作做好在该动作里记结果会议尚未进行，目标继续跟进；未完成的动作仍在。
一次见面已结束完成本次日程，补实际交流和复盘客户可能还在等方案或审批，目标不自动结束。
整个目标已达成，或决定不再推进“更多 → 目标 / 事项状态”，选“已结束”和结束原因保留全部记录。已有安排不会自动取消，需要取消时核对原安排。

收起事项时，先决定提醒要不要保留

“更多 → 归档”用于暂时收起，“移到回收站”用于不再需要的临时想法。窗口先列仍有效的安排，再选保留已有安排与提醒（默认）或停止关联的有效提醒。保留时事项从日常列表隐藏，日程仍然有效；共享安排和新状态有冲突时会阻止提交，先重新核对。

在“跟进事项 → 已归档 / 回收站”打开后可点“恢复事项”。恢复只恢复展示，已停止或取消的提醒不会重新启动；撤销归组也不会启动提醒。本机版到点通知能力仍以实际运行模式为准，不能把保存安排当成已送达企业微信。

每天只记住两个入口推进哪件事：打开“跟进事项”，在同一处继续说、看步骤和资料。什么时候去做：打开“日程”，看实际安排，需要继续业务时回到它的所属事项。

三条流程：从一句话到持续推进

以下为虚构操作示例，不会自动写入你的客户资料，也未声称演练环境已预置这些事项。可先在独立演练环境练习；离线模型只支持已有固定句式，其他原话仍会保存。使用正式模型时，核对回执、归属和实际结果，不为练习重写已有客户记录。

案例一 · 一次电力汇报，两个准备动作

目标：准备一份能向客户讲清电力密码产品的汇报材料，而不是把“改结构”“补产品”当成两个互不相关的事项。

在首页说这一段
我要给澄川集团做电力密码方案汇报，先按产品线重组电力PPT，再补充配网主站指令防篡改装置的产品化内容。这两步都是为了准备同一次汇报，时间还没定。
  1. 保存后核对“准备电力密码方案汇报”这一目标及客户归属。模型已明确识别时，在同一件事里看两个准备动作；若结果拆散，从“归入另一件事”核对共同目标后合并。

待落实安排：秘书帮你把活动定下来

想到一次拜访、培训或电话，就在工作台告诉秘书。信息不完整也先留下。回执点查看这次计划，或从待落实安排继续。队列初次打开显示全部待落实，没有期限、没有回看点的活动也在；“今天”“本周”“本月”是筛选，局部为空时可以回到全部。

想只看同一个对象，点卡片归属的客户、联系人或项目名称；在事项的时间安排处，也可以查看该事项的全部安排。切换“今天”“全部”等筛选仍保留当前对象范围；清除当前对象范围后，回到所有对象的安排。

你在说什么秘书如何记录不会混到哪里
本周把下月拜访时间定下来本周是确定安排的期限，下月是拟执行范围。不会把本周末当成拜访钟点。
周五再问一下对方下一推进点：周五回看回复或联系对方。不会因此创建一场周五拜访。
下周四下午三点已约好，按这个安排依据齐全时落实实际活动时间。执行日程与推进提示分别保存。
提前一小时提醒；或者不用提醒执行提醒按你的明确选择保存。不用提前提醒仍可安排日程。

“本周去拜访”表示执行范围；“本周约一下”含义不明时先核对是这周去还是这周定时间。只说日期、上午或下午时，页面保留这种精度，不冒充你说了某个钟点。

流程一 · 自己能决定的安排

  1. 说本周把下个月培训时间定下来，讲义还要准备。先保留待落实安排与准备工作。
  2. 在同一计划继续说安排11月12日下午三点，我给团队培训，不用提醒。自己能决定、时间明确时直接落实，不要求客户答应，也不追问默认提前多久。
  3. 从日程看实际活动；讲义准备仍是关联待办。时间定下不表示讲义完成，培训结束也不表示整个项目结束。

流程二 · 等对方回复，先日期再钟点

  1. 说本周把下周拜访定下来，周五再问客户。在同一计划记录期限与下一推进点。
  2. 发了两个候选就补候选；你选一个日期，仅代表自己的选择，仍要看对方是否答应。
  3. 如果只需先定哪天，明确说先定日期即可，对方确认12号，几点没定。日程显示“日期已定，钟点待定”，不生成猜测时刻的日程。
  4. 点继续确定钟点。日期没变就保留已同意的日期；补我想安排12号15点，等他确认钟点。只等待这个钟点的回复。再说对方已同意15点、按此安排，落实同一计划。对方确认日期却不同意某个钟点时，保留日期，钟点继续商量。

流程三 · 改期时仍看得见原安排

  1. 已有周四安排，再说可能改周五，等他回复。页面同时显示当前有效安排和拟改安排。
  2. 改期，时间还没定。保留原有效日程及执行提醒。只有明确说原时间不去了，新时间还没定。才撤销原日程；原话和取消历史保留。
  3. 新时间有冲突，先继续选时间，原安排仍有效。新安排核对通过后更新同一日程，旧执行提醒失效。
  4. 只是停止讨论改期，选放弃本轮协调；只想暂时别催，选暂缓协调，状态显示“暂缓推进”。这两项都不取消有效活动。确实不举办才选取消这次活动并核对影响。

流程四 · 超过期限、暂缓与恢复

  1. “希望本月定下来”和“最晚本月必须定下来”分别显示希望期限、最晚期限。超过期限仍保留安排，你可以记录进展、改期限或暂缓。
  2. 说问过了，仍没回复，周五上午再看。记录实际推进，给一个新回看点。只说“还在等”不会冒充已经联系过。未启用自动推进策略时，秘书只建议新点，不无限催问。
  3. 点恢复协调重新推进，明确选沿用仍有效的点、现在推进或新的点。旧点已经过期则需要重新选择，不补发一串历史提示。
  4. 来源归档或回收后再恢复，只恢复可见性；要重新催办，还需明确恢复协调。归档安排前核对窗口里的执行日程影响，不凭“收起来”推断活动已取消。
网页提醒怎么用

同一安排同一天的推进、临近期限或超期原因汇在一张提醒卡中。标记已读只表示看过，不代表问过客户或安排已落实。明确说“周五再看”后，回看前遵守安静期；到点展示当前有效原因。页面关闭不丢到期状态，服务运行后重新打开可见。这是网页提示，不能据此判断手机或企业微信已经送达。

如果想让秘书在没给推进点时自动采用建议，从队列提醒设置启用默认推进策略。默认关闭；已有明确回看点优先，设置不会改写已建立安排。具体操作与当前状态始终以计划回执为准。

后来的进展，要保留后来的时间

已有材料发生时间与原交流不同，确认确实属于同一场交流后，勾选“我确认材料属于所选交流，保留材料自己的实际时间”再关联。这样保留各自时间，不把今天的反馈写成昨天会议里已经说过的话。

材料实际发生时间尚未核实时，当前整理会保留时间依据并要求补充，不自动拟安排；即使原文里有绝对日期，也请在采纳后的待办“补充具体时间”核对后确认。不要为了生成日程，把保存时间填成会议发生时间。

当前软件的 MCP 连接只按完整标题读取转写和摘要，尚未接入录音列表／搜索／完成事件接口，因此还不能自动发现手机刚录的所有录音。录音进入读取队列后可自动拉取和整理。很长的材料归属识别使用标题及前 20,000 字，候选仍需对照完整来源核对。演练不连接聆记和真实语音服务。

  3. 打开“核对”，处理近期资料与行动；不适用的建议“不采纳”，暂时决定不了的“稍后处理”。
  4. 检查等待反馈事项；有检查日期时联系对应的人，记录实际反馈。

每次交流后：留下可接续的记录

  1. 随口记或向同一场客户交流追加复盘，先校对公司名、人物和术语。
  2. 分清客户明确说了什么、我观察到什么、双方谁答应做什么。
  3. 采纳需要推进的事项，时间明确后单独确认日程。
  4. 做完行动就“完成跟进并记结果”，写结果；下一步还没约时间就只留待办。

每周一次：把项目与联系节奏校准

  1. 按客户查看未完行动与等待反馈，核对项目范围、阻力、采购路径和决策链。
  2. 逐个检查金额是估算、预算、报价还是合同；审批“未知／未确认审批／已批准”分别有依据。
  3. 更新项目阶段，检查来源与行动归属。多个项目不能用客户总金额代替。
  4. 检查联系人是否仍活跃，离岗或不再对接可“归档联系人”，历史仍保留。
  5. 在“基本资料”维护“建议联系间隔 / 天”。它只提示联系节奏，具体拜访时间仍由你确认。
  6. 查看“核对”中的“稍后处理”“已不采纳”，需要重新决定时“恢复到待核对”。有新依据的项可能重新提示，应核对新增信息。

10 · 改错、重复、失败与草稿恢复

保存原话时换了页面，怎样找回

迟到的保存结果会更新原请求，当前新输入继续保留。如果保存状态不明，回工作台查看“上次输入，继续保存”，打开原话核对归属再重试。同样原话、归属和原始转写原样重试不会重复保存；修改这些内容会作为新的输入。浏览器会话中的恢复稿要继续保存，才成为后台持久记录。

补画像时切换字段，怎样继续原稿

行业、区域、需求等字段分别保留本次未提交草稿，包括内容、信息性质和依据。切回原字段可继续填写；点“保存画像”只提交当前选择的一项。需要修改多个字段时逐项保存，草稿不会自动写入客户档案。

只结束预约，事情还没落实

在日程点“仅完成日程”，只表示本次执行安排结束。未完成的跟进仍留在“我的工作”、客户未完行动与截止／检查节点，项目不把它计为跟进完成。真正落实后打开该待办，点“完成跟进并记结果”保存实际结果。

重新纳入一份曾排除的来源

在该来源“明确这份来源本次如何使用”把决定改为“纳入核对”，核对本次说明再保存。仍未改写的旧排除说明会清空，原理由继续保留在“来源使用决定历史”。如果你已经写了新的说明，它会保留；不要用“暂不作为依据”的旧理由代表本次纳入决定。

转写过程中关掉窗口，回来找文字

启用专业识别后，如果转写尚未返回就关闭窗口，已完成的文字会保留为待恢复转写；重新打开原客户或交流的语音入口，先核对原归属，再点“恢复到本轮文字”。它不会自动填进后来打开的另一位客户。恢复后核对文字并保存，避免把同一段重复录入。

等待麦克风授权时关闭窗口，迟到的授权不会继续启动录音。此保护已用模拟权限和转写响应验证；真实音频质量仍需配置识别服务后另测。

公司、人物或专业词识别错了

短记录：打开记录→“纠正识别文字”或“编辑记录”→修改全文→“保存并重新整理”。首次原文仍保留。仅保存字段则用“仅保存修改”；已有提醒可选“同步当前待办提醒 · 生成变更提案，确认后生效”或“仅修改记录 · 原提醒保持现状”。

完整材料：打开材料，展开“2 · 人工核对与修正：归属、实际时间、人物和文字”，改客户、实际时间或“修正后的全文”→“保存修正并重新整理”。材料产生的待办详情里只展示摘录，改原文应点“打开完整材料重新整理”。没有改内容就保存，不会新增版本或废掉已确认的项目归属和安排；要明确再跑一次整理，用“重新处理”。

成功时看到什么当前人工修正版与首次来源版本可分别查看。修正文只保存在秘书后台，不写回聆记；已采纳的行动和已确认日程仍需单独核对。
不确定这段话属于哪位客户

随口记先点“核对这句话的客户归属”，看公司名、简称、联系人等理由后选客户。已有记录可“编辑记录”补充“关联客户”；材料在人工核对区补归属。多个同名联系人时，先问清所属公司。

成功时看到什么客户候选有理由，多候选要求你明确选择；不能仅靠“李经理”“周工”强行写入某家企业。
同一事项重复出现，或来源之间有冲突

在客户交流“合并重复事项”里勾选确为同一行动的项→“合并选中重复事项”。先核对责任人、事情、时间与来源；不同客户或不同执行主体不是同一行动。

若一个来源说上午10点、另一个说下午3点，先打开“核对 / 修正”确认真实约定，再决定合并或采纳。后续来源不会自动替你改已确认日程；请回原事项核对安排变更。

成功时看到什么同一行动保留多份依据，冲突明确提示，不静默选择其中一个时间。
聆记完整标题填写错，导入失败
  1. 打开“查看 / 重试”，查看实际失败原因。
  2. 点“纠正标题”，从聆记复制完全一致的完整标题，避免语音复述标题；同名录音建议先在聆记改为唯一标题。
  3. 保存修正后，根据当前状态点“重新处理”或“重新读取聆记”。
  4. 无法读取时，点“粘贴人工转写继续”，填核对过的完整文字，保存修正并重新整理。

客户交流里未读取来源可能阻塞采纳。若明确本次不使用，展开“明确这份来源本次如何使用”→选择“本次暂不使用，保留原材料”→填写必需的理由→“保存本次来源决定”。“稍后核对，继续保留采纳保护”仍会阻塞，需要之后读取核对。

成功时看到什么失败材料原文或标题保留，来源使用决定有历史。排除来源不删除材料；重新纳入会要求核对影响。
模型失败、显示“已配置”却没整理成功

“已配置”表示找到配置，真实凭据、余额和网络是否可用要到调用时才能验证。原文保存后仍可手工核对，配置可用后再从材料或记录重新整理。正式环境不会用模拟结果冒充成功；本轮独立演练会明确标为离线示例。

成功时看到什么真实错误状态与已保存原文可见。不能把空结果当成“没有待办”，也不能把演练结果当成真实模型质量测试。
关掉编辑弹窗，草稿去哪了

首页未提交的一句话离页再回来、刷新后仍保留。编辑中“关闭”保留当前浏览器会话草稿；再次打开可显示“已恢复未提交草稿”。从客户里新建记录时，各客户的草稿分别保留，回原客户继续；全局新建入口中的旧草稿仍从全局入口找回。后台已有较新修改时，先显示最新内容，旧稿由你点“恢复旧草稿供对照”再比较，不能直接覆盖。

两个窗口编辑同一条记录时，旧窗口不能覆盖较新的保存；版本冲突会保留原输入，重新打开最新资料并对照草稿再提交。浏览器草稿不等于已经保存的记录；已提交的原文和材料版本才是持久资料。手机记录后要换电脑继续，先点保存，电脑再打开同一条记录；未提交的浏览器草稿不会自动同步到另一台设备。

成功时看到什么同一会话重新打开时能恢复输入或选择恢复旧稿；成功保存后回到详情，旧草稿不再次覆盖已保存的新内容。
从历程打开原文，再回到刚才的位置

在客户或联系人“跟进历程”筛选项目、记录类型和关键词，展开“完整内容与来源”再打开来源。点“返回……的跟进历程”后，系统重新核对最新资料，再恢复仍有效的展开记录与阅读位置。来源已更改或隐藏时会提示重新定位，不能继续展示旧正文。另一个客户、联系人或项目不会继承这次阅读状态。

行动来源提示归属变化，怎样核对

待办里的“来自推进计划”或“来自 AI 跟进讨论”可回看原输入、回复和采用结果。系统按采用时的实际客户、项目与人物比较当前归属；全局计划没有先选客户，本身不会被当成归属后来变化。旧来源缺少可靠历史时保持中性提示。出现明确变更或关系待核对时，先看原稿及当前关联，再决定后续行动；来源回看不会自动修改客户或安排。

把建议暂时放下，之后再恢复

顶部“核对”→“稍后处理 · 选择回看时间”→填未来日期时间与选填说明→“保存回看时间”。不适用则“不采纳”；需要重新决定，到“稍后处理”或“已不采纳”页签点“恢复到待核对”。

同样依据重新整理不应把已不采纳的建议重新推回来；确有新来源变化时会再次提示，先看新证据。

成功时看到什么统一核对和来源页状态一致，处理说明与原始依据可回看；恢复只是回到待决定，不是自动采纳。
语音按钮灰色，或者行业词识别不准

“记录方式”→“语音 / 行业热词”可保存“行业热词 / 客户专有名词”，每行一个词或逗号分隔→“保存热词”。客户名称、简称和活跃联系人会加入接入的识别词表。

专业 ASR 未配置时，语音入口先提供可用的文字框：用输入法语音输入或粘贴转写，再核对文字。“开始录音”“结束录音”“转写成文字”依赖实际识别服务与浏览器权限；文件格式、大小和时长按界面能力提示。热词保存本身不等于已经启用识别。已完成专业转写后再切到同一客户的随口记，原始转写与人工校正文分别保留；保存前可展开原始转写对照。

成功时看到什么原始转写、人工修正、AI理解三层分开；服务未启用有明确提示。真实识别准确率需另外测试。

新版 · 一家单位，多位客户，多条项目线

把“客户”分成三层理解：单位负责组织背景；联系人负责个人职责、偏好与沟通方式；项目负责需求、预算、采购路径与决策关系。单位的上下级不等于项目的审批关系。

1先建立单位和具体的人

在“客户”新建单位；新建或“单位关系”中可选择集团、公司、部门等类型与上级单位。进入单位后添加联系人，填写部门和职务。同一单位的两位“王工”可以按部门或不同电话区分；不知道具体是哪一位时先保留原话，不强行合并。

检查结果单位关系能回看上级、下属与各自联系人；个人画像始终跟着这个人保存。

2每个项目分别核对参与单位与决策人

建立项目后点“联系人 / 决策关系”。先记录本项目有哪些参与单位，再为具体联系人选择预算决策、最终审批、技术评审、采购、推动者等角色。同一人可以有多个角色，同一角色也可以有多人；人物可以分别参与不同项目。外部合作单位需明确加入本项目的参与单位后，再选择其联系人。

角色之外，补“关注点”“下一步”“接触情况”和原话依据。不要仅凭“领导”“主任”的职务认定其有审批权。归档角色保留历史；需要恢复时重新核对本项目关系。

检查结果打开项目甲和项目乙，看到各自的角色、依据和项目资料；改项目名称、阶段或金额时不丢决策关系。

3日常说话，逐步积累画像

继续用首页一句话、聆记录音材料、交流复盘和 AI 讨论记录。原文归到单位后，后台持续生成“待核对画像”，按单位、联系人或项目提出候选。第一次开启先建立扫描起点；想补整理以前的交流，点“整理已有交流”。未配置真实模型时会显示“规则提取候选”，不能把它当作完整理解。

点“逐项核对”，先选具体的人或项目，查看当前资料与新原话，再确认或不采用。金额、采购时点、预算审批等项目资料留在该项目；个人偏好留在对应联系人；明确的决策权限进入项目决策关系核对。旧值和来源继续保留。

检查结果候选确认后才写入相应画像。两个窗口发生修改冲突时，刷新最新资料再核对，旧输入仍保留；来源原文已修改或排除时，需要重新整理。

4有目的地了解客户，而非一次填完表

在项目画像里看“下一次交流，先弄清什么”：每项目优先列出三个成交关键缺口，例如业务价值、预算是否批准、谁能批准和采购路径。知道答案就点“补充已知资料”；不确定就点“与 AI 讨论”，问题会带入该项目的讨论输入框，由你发送；需要跟进就“采纳为待办”。

检查结果补齐后缺口会减少；重复采纳打开已有待办；采纳不自动排日程，执行时间仍需你补充确认。

“还需要了解的关键联系人”会提示具体人物的工作目标、考核重点、关注点、职责或沟通方式。点“补充个人画像”，资料写入这个人所属单位；点“与 AI 讨论”，问题带入当前项目，由你补充后发送。每项目最多两个重点，不凭职务自动推断权限。

三个新场景，按这个思路练

  1. 同一家单位，两位王工、两个项目：在虚构“禾川数据中心”分别建“技术部王工”和“采购部王工”。数据库加密项目里前者负责技术评审、后者负责采购；密码机项目里采购部王工可同时承担预算决策。逐个打开项目核对，不能把一个项目的预算和权限复制到另一个。
  2. 集团和子公司共同采购：虚构“岚川集团”下建立“岚川制造”；项目放在制造公司，加入集团为本项目采购参与单位。选择制造公司的技术人员和集团的采购人员；若涉及外部集成商，明确加参与单位并写依据，再加其联系人。
  3. 复盘发现旧信息不对：先保存“试点预算尚未批准”，后来记录“客户确认预算已经批准，采购会需再确认”。整理后核对新原话、项目归属和旧值；更新本项目资料，再把“确认采购会时间”采纳为待办，明确时间后安排。不要因为模型候选里提到日期就认为日程已生效。

公开资料怎样辅助画像

用“粘贴公开资料”保存地址、发布日期和原文，核对单位身份与时效后作为观察。配置公开检索服务后可点“检索公开资料”；在“自动整理与官方域名”核对域名并开启自动检索后，后台按周期辅助补充单位背景。公开资料始终先形成候选，不自动成为内部项目预算或个人决策权。

当前启用范围

演练版没有真实联网或模型理解，新场景建议通过手工建立和补充体验流程。正式本机版沿用已有模型配置；官方 DeepSeek API 的公开检索会复用已有配置；可选 PROFILE_WEB_SEARCH_API_KEY 使用 Tavily。没有可用联网通道时仍可粘贴公开原文。发布日与抓取日分别保留，未知发布时间不会用抓取时间替代。

AI 回复可列行动、待核实问题及风险。你的个人思考和历史 AI 建议会保留性质；不会变成客户已确认事实。资料修正后，旧建议会提示重新讨论与核对。

让秘书准备，核对后落实

秘书既能记录事实，也能理解你的工作目标。准备稿可以修改、保存、离开后再回来；保存准备稿不改正式资料，确认所选内容才采用。未指定时间的行动保持未排期。

放下准备稿，之后从哪里接着做

先点“保存准备稿”，之后从顶部“核对”找到“继续核对这份准备稿”。卡片会显示客户、联系人、项目或原待办，打开的是同一份稿，原输入、编辑和选中内容都会保留。全部采用或取消后，它会离开待核对；采用后的待办仍可在“这一步从哪里来”回看原准备稿或原 AI 讨论。

交流整理稿也能从顶部“核对”恢复。想暂时收尾，先保存修改，再点“本次先整理到这里”：只从待核对中移出，原文、已经采用的待办和日程保留；以后从原记录继续整理即可。

采用AI建议或交流中的下一步时，可在“这项待办明确关联谁”选择姓名、部门和单位。选择只关联未来行动，不代表已经交流；文字沟通线索不会自动选中同名的人。没选人也可以先存待办，再从详情补充。

没有说预计多久，用时可以空着，先保存未排期待办。确认具体新日程时，再填写预计用时；截止日期、检查日期和具体日程分别核对。

成功时看到什么准备、讨论或查询目标没有冒充客户交流；候选名称不必与你说的简称完全相同。没有确定对象时选择已有单位，不会自动创建同名单位。

2一份输入，一处核对

打开原记录、材料或客户交流，点“核对秘书准备稿”。按实际内容展示资料、相关人、行动和安排，原文与发生时间可以对照。修改有用建议、勾选本次要采用的项，点“确认所选内容与安排”。也可以只保存准备稿。

归属不明时先选具体的人或项目；公开观察不会直接变成客户事实。改过归属需要先保存，对照该对象的已有资料后再确认。结果回执会指出已采用、需要核对或失败的内容，成功项不会因重试重复创建。

3会前准备与会后复盘

从客户的跟进页、项目总览或联系人历程点“准备拜访／准备这次沟通”，自动带当前对象；先看已有承诺、未完事项、材料和少量问题。想调整本次要问什么，点“修改本次要问的问题”，页面会滚动到第一项可编辑行动的“推进说明”。把问题改成自己的话，例如“先问系统负责人：兼容验证要覆盖哪两套系统、由谁确认结果？”，再点“保存准备稿”；需要落地时另行勾选该行动，确认采用。

这个入口只把光标带到说明框，不覆盖你已写的内容，也不会替你勾选、保存或建立待办。没有可编辑行动时不会提供该入口；已采用的行动继续从待办详情修改。会后用“会后复盘”补实际交流与自己的判断，建议核对后才能变成下一步。

联系人准备只使用直接交流和明确与他有关的内容。项目中的其他人不会因此自动算作参会；需要扩展背景可回到单位或项目维度。

4给旧行动记实际结果

打开待办，点“整理推进反馈”，填写实际进展。全局入口先选原待办。新准备稿把第一项推进建议放进“下一步”供你修改，展开“最初建议”可对照依据；它不代表客户已经反馈，也不会自动建立行动。核对实际结果、对原事项的处理、下一步和谁来推进，再勾选确认；时间未知继续留空。

只收到一部分反馈，例如测试条件已有、采购牵头人仍未知：选择“部分已落实”，分别填写已落实和仍待跟进的内容。确认后已落实部分单独留结果，原事项继续跟进剩余部分，原话保留；不会重复建立一份剩余待办，也不会同时采用第三项建议。若原事项已有安排，先核对旧安排再拆分。

长段反馈会明确标出结果节选，并展开完整原话。请特别核对结尾的未完成条件，再把“这次结果”改成你确认的表达。保存准备稿只保留编辑，正式结果需另行确认。

成功时看到什么回执可“回看原事项与反馈”或“打开接续待办”；部分落实时分别打开已落实和剩余部分。选择继续或等待不会完成原事项；完成日程也不等于业务已经落实。快捷“完成并记结果”中，可顺手填写下一步并明确选责任人。

首页或“总览 → 我的工作”点“今日计划／本周计划／本月计划”。可修改起始日期和重点，秘书展示本人行动、等待反馈、未排期及已有日程。准备稿中的数量是准备时快照；实时情况看总览或日程。

同一个单位、同一个人参与不同项目，如何继续跟进
  1. 单位层级记录行政隶属。分别建立项目，在各项目“谁参与、谁决定”中核对参与人角色；职务不自动代表预算或审批权。

  3. 从联系人探索问题或历程“讨论下一步”进入，秘书带入这个人和当前项目。左侧可回看项目范围、本项目角色与依据；思考、提及与实际直接交流分别保留。

  5. 历史参与单位恢复会预填原角色和依据，供你核对后恢复。隐式主单位可补充作用，不提供无法执行的归档选项；归档项目先恢复再改变参与关系。

现场录音、隔日复盘，如何接成下一步
  1. 现场用聆记录音，回到材料页按完整标题读取，或粘贴已经核对的转写。填写实际发生时间；不确定就留空。记录时间由系统保存。
  2. 先核对行业错字与人物，将材料归入对应交流。人工修正与首次来源原文分别保留；纠错不新增一次客户拜访。
  3. 隔天想到新判断，打开原交流添加“我的复盘”。说明是在复述原交流还是后来的新情况；个人判断保留为观察，不替客户承诺。
  4. 补充来源后，打开秘书准备稿。如果显示来源变化，点“按最新来源重新整理”；“刷新状态与最新资料”只读取进度。旧编辑保留供对照，重新整理不会自动采用。
  5. 先看下一步与当前待核对项，历史画像在“已处理 / 历史画像”中展开。核对行动项目、责任人与依据，修改后选择采用。未约定执行时间时保留未排期。

  1. 先看要推进什么。在“总览 → 我的工作”打开本人行动、等待反馈或逾期的对应列表。队列可以继续搜索、分页和查看详情；回到全部记录时再看其他类型。等待反馈包含已经确认的推进结果，未采用的准备稿不会改变正式状态。
  2. 再看准备哪个时间范围。选择今日、本周或本月计划，核对参考日期和页面显示的实际窗口。默认日期随期间切换；自己修改的日期保留。要接着改旧稿，使用“继续最近计划”，核对它的日期范围；准备当前范围则使用当前计划入口。
  3. 分清谁执行、我何时检查。自己负责的行动可安排执行时间；等客户或同事反馈时，可给自己安排一次检查，原责任仍属于客户或同事。只知道检查日期就只填日期，不生成一个猜测时刻。没有明确时间的事项继续留在待办。
  4. 时间和依据分别核对。补充用时或日期是你本次确认的信息，不会冒充原客户说过的话。原资料与历史依据可回看；修改一个时间字段，不改其他未修改字段的独立依据。取消某个日期时，这个日期的依据一并清除。
  5. 保存稿，再确认所选安排。暂时没核对完可保存准备稿后关闭，之后从同一计划入口继续最近稿，或从顶部“核对”恢复。只有确认所选项才改变日程。部分项成功、部分项冲突时，先看逐项回执；成功项重试不会重复建立。
  6. 遇到冲突，按具体时段修改。页面会说明冲突事项和起止时间。修改拟安排后重新核对；冲突中的拟安排仍未生效，原日程保持。重开准备稿也会保留这个状态。
  7. 日程回到日、周、月查看。卡片显示有效项目范围；跨午夜的安排会在所占的日期显示延续提示，原开始和结束时间仍可对照。日程完成、取消安排、业务落实是不同操作：业务结果从原待办记录，取消日程后未完成的业务仍要继续跟进。

同时打开两个窗口时，旧窗口不能覆盖后来核对的安排。遇到“资料已变化”，保留原输入，刷新核对最新状态后再提交。这些流程在8766的隔离示例中演练；正式AI、语音、搜索和企业微信提醒需要相应服务配置。

一整天怎么用：随记、讨论、安排、回来报结果
  1. 早上打开“总览 → 我的工作”，先看自己的行动、等待反馈与待整理；再看具体项目卡点。
  2. 现场把客户原话、自己的承诺和个人判断一起记下，或用聆记录音。先保存，不必当场填全画像。保存成功后可离开，回来从已保存记录继续；失败的输入仍可续办。保存过程中再输入的新话不会随旧回执一起清空。
  3. 有空核对必要对象。从联系人历程带原文讨论“下一步先核实什么”。采用表单先看行动、责任和相关人；需要时展开材料与完成标志。联系人整体讨论可显式选此人参与的本单位项目；没有确定项目就先不选。要让AI重新考虑某项目预算或采购条件，另在该项目范围讨论。
  4. 行动未知时间先留待办；要执行时在日、周、月计划补时段、用时，再确认。客户说还要问运维时，保留客户等待，可给自己设回访检查日期；不要替对方补回复时刻。
  5. 回来记结果：例如“资料已发；测试条件已收到；审批人仍未知”。只落实一部分时核对已落实结果与原事项剩余工作，不能完成整条等待项。新想法先作为项目研判资料，确有具体下一步才采用行动。
改标题、核对角色：哪些操作需要重新确认

有完整正文的独立随记，仅整理易读标题且客户、正文和性质都没变时，保留此前有效的项目和人物关系。原来已失效、归档、合并或历史来源不会因此恢复；仅靠标题记录内容的条目仍需核对。旧AI整理继续按原来源版本检查，不能把整理标题当成重新认可旧建议。

在项目决策关系中，可先记未知或个人观察。明确了解到某人的本项目角色后，填角色、原话依据及实际接触情况，再显式勾选本次核对。系统记录的是你本次核对的时间，不是会谈发生时间，更不是客户新承诺。普通修改备注不会刷新核对时间；角色、依据或接触等关键信息变化但未重新核对时，旧核实状态撤回，提醒继续了解。预算、采购和审批权限仍分别核实，不从职务推断。

本次核对控件与采用时选项目，需要相应后台版本返回能力信息。旧后台缺少该能力时不会发送不支持的新字段；正式服务切换后再验收完整效果。

研究、语音和聆记的能力边界

单位资料的“公开资料”入口可填写公开链接，点“读取链接正文”，核对正文和年份后保存候选；需登录、附件或脚本网页可手动粘贴。深度搜索需要真实搜索服务配置。现场录音可继续用聆记；当前按完整标题拉取并自动整理，列表／完成事件接口尚未验证，不能自动发现所有新录音。专业语音服务已配置时，网页停止录音后自动转写；未配置时用输入法语音或聆记文字。演练中的AI和网页均为合成，不访问真实服务。

待办与安排详情：先处理这一件事

打开详情，按“标题与对象 → 当前情况 → 本次推进 → 相关信息与准备 → 来源与历史”阅读。标题只显示一次，长标题可在原位置展开；完整资料和历史按需打开。

1先看当前情况，再补一句进展

普通待办默认“记录进展”。例如写“已联系，客户周五回复”，点底部唯一的“保存进展”。即使文字里说“这个完成了”，也只是追加进展；若要结束待办，请明确更换本次处理为“完成跟进并保存结果”。

成功时看到什么回执说明进展已保存，当前情况和历史更新，原待办与日程状态保持。完成目的另列将结束的日程和拒绝的提案，核对范围后才提交。

2在同一个处理区选择本次目的

用“更换本次处理”选择记录、整理、补充安排、调整推进点或明确完成。一次只提交所选目的，其他草稿独立保留。安排的“补充安排 · 秘书理解”可以一句话补齐信息；“只记录进展”保留当前检查点。附件留在补充安排草稿，切换到不支持附件的目的时不会随此次发送。

成功时看到什么“原话已保存，正在整理”只表示原话已接收；整理结束后看当前真实安排。只有“已加入正式日程”等生效回执及真实执行时间才表示已经落实。失败可以重试已保存原话，不需要重新录一遍。

3区分执行、期限与推进点

执行时间表示什么时候去做；确定期限表示何时前定下来；下一推进点表示何时再问及问什么。它们分别编辑。“周五再问”不会移成周五见面。有可靠关联安排时，从“关联安排与日程”进入对应活动；独立旧待办仍可保存待确认提案，随后明确确认。若同一记录可能含多次活动，点“核对全部关联活动”，按真实活动选择。

成功时看到什么改期尚在商量时，旧有效时间与拟改时间并列。暂停或放弃协调保留旧日程；撤销当前日程、取消整次活动和完成跟进分别显示自己的影响范围。

4回看资料后返回继续写

相关资料、原话和历史放在下方折叠区。进入安排或来源后，用头部“返回待办详情 / 返回安排详情”回到原位置，保留草稿、焦点和展开状态。资料版本有变化时，先点“保留输入，重新核对”，对照最新状态重新核对授权；页面不会把旧确认自动套到新版本。

归档、删除、编辑等维护入口在“更多操作”。归档组可能同时停止多条日程，预览会列出实际范围；恢复只恢复可见性，停止的日程仍需重新安排。网络结果未知的普通进展先回看历史，明确决定后再追加，避免重复。
