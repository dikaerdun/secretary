# 客户秘书后台使用与维护

## 访问

- 本次内网地址：http://<your-server>:8765
- 登录只需后台口令，无需用户名。初始口令保存在本地 `secretary/deploy/web-access.local.json`，不写入源码、日志或此文档。
- 电脑和手机连到能访问服务器的公司网络即可使用。当前没有替用户建立公网映射。
- 应用与机器人共用 `personal-secretary.service`；后台与机器人同一进程共享修改锁和数据库。

## 推荐流程

1. 在“客户”只填名称即可建档，也可在企业微信说“新建客户……”后确认资料草稿。金额未知就留空，系统显示“未明确”，不会当作零；联系人、商机阶段及画像逐步补齐。
2. 拜访后给企业微信秘书发语音或文字，或在后台“随口记”输入。一次可以同时说客户资料、现场想法和下一步约定；秘书保存原话并整理为资料草稿、交流纪要和待办。后台“语音”入口的专业录音转写需先配置服务，条件见下文。
3. 核对统一结果：C 编号用于确认客户资料，P 编号用于确认日程，AI 建议需要你采纳。带明确未来时间的承诺会先生成待确认 P；未说明时间的事项保留待补时间，不擅自排期。
4. 识别有误时打开记录编辑，核对标题、正文、客户、类型和状态，再点“保存并重新整理”。选择“不关联客户”会清除原归属。首次原话单独保留；已有活动提醒会显示原来的标题和时间，供你核对。
5. 将无时间的明确待办或 AI 建议逐项“加入跟进”，在待办里补时间，再“确认并启用提醒”。重复采纳不会重复建立待办；仅保存、采纳或设置时间都不会启用新提醒。
6. 每天打开首页，按“逾期待处理、今天要做、日程待确认、待补时间”处理。统一待确认入口可集中核对 C、P 和待采纳行动。日/周/月日程可打开客户或原始记录，也可改期、取消或安排下一次拜访。
7. 记录新进展时，“保存进展”追加到时间线；“保存并整理本次沟通”会建立关联原记录的独立交流，提炼新的待办。完成待办会停止当前活动提醒并撤回未确认提案，旧 P 不能再将已完成事项启用。
8. 拜访前用客户页的一分钟简报看目标、诉求、待办和主联系人；查看推进建议中的优先动作、准备材料、提问话术和依据。执行后反馈“已完成、受阻、暂缓或不适用”，秘书据此思考下一步。

不会自动联系客户，也不会把 AI 建议当成已承诺事项。时间不明的待办可长期待安排；普通手工记录可点“帮我整理”。模型只把本次原话中的明确承诺作为承诺依据，同客户历史交流用于背景。原有单事项输入和明确确认规则继续有效。

未提交的表单会在当前浏览器会话保留草稿，刷新后可恢复；关闭编辑框或退出登录时提示未保存内容。这不等于已保存到服务器，也不跨设备同步，仍应及时提交。手机正文及按钮已按窄屏优化。

## 数据安全与商用密码客户画像

客户名称必填，其余逐次补充。公司画像分为客户背景、安全与密码场景、需求与验收、商机推进，共26个可选属性；联系人另有角色和电话、决策影响、关注重点、联系渠道/时段、材料深度、喜好、沟通注意事项和关系背景。每家客户可以有多位联系人；当前每客户仍是一笔商机金额，多个独立商机项目留待后续。

首页“随口记”接受每次最多 6000 字；可使用企业微信语音转写或手机输入法语音输入，核对文字后提交。网页可先明确选择客户，再说“他”或“这家客户”；从客户页进入时预选当前客户，全局入口默认不选，不会暗用最近客户。同一家客户的多人交流可以一次完整记录。涉及多家公司、重名或无法确定归属时，秘书会保留原话并请你选择客户或补充信息；候选按钮可确认本条交流的归属，涉及多家时按客户分别整理。示例：

- “新建客户华辰科技，联系人王总，关注数据库加密和密钥管理，希望先微信发材料。”
- “补充客户华辰科技，联系人王总，我感觉他更关注实施周期。”
- “记录客户华辰科技的交流：今天王总和李工都在，王总关心实施周期，李工关心接口兼容，我答应补充部署方案，暂时没约具体时间。”
- “查看客户华辰科技”读取拜访前速览。

新建/更新资料先返回 C 编号草稿及修改前后差异。说“确认客户 C1”写入，或“取消客户 C1”；“客户待确认”列出草稿，“查看客户草稿 C1”查看详情。网页也能核对确认。同次描述的交流纪要和后续行动会一起呈现：确认 C 会将来源交流及尚未分配客户的关联待办挂到该客户，日程仍按 P 提案单独确认。

档案中的“补充画像”和联系人卡片支持手工维护。每条属性保留原话依据、来源和时间；“我感觉/我观察”等标成个人观察、待核实，拜访简报也会区分。AI 不补造喜好、采购预算或合规结论。草稿要修改的字段或来源交流发生变化时，旧草稿会过期；改了其他不相关字段，仍可继续确认。

客户基本资料可以填写简称/别名、建议联系周期和主联系人。简称用于查找、归属匹配及后台专业转写词表；同一成员下的客户名称和简称需避免重名。建议联系周期用于记录跟进习惯，不自动生成循环提醒。联系人卡片支持拨号、复制电话及归档；离任联系人可以归档，原有沟通画像与修改历史保留，后续查找和推进建议使用有效联系人。每个客户当前仍只有一笔商机金额，未知留空、明确为零填 0。

拜访前打开客户页，可先看目标、当前诉求、未完成记录、最近交流和联系人沟通偏好，再按需展开详细字段。日程沿用日/周/月视图。模型失败仍保留原话，人工修改不会被正在生成的旧分析覆盖。

## 让秘书思考销售推进

客户档案的“推进建议”独立于事实画像和本次交流纪要，页面会标明“AI 建议”。新记录和追加跟进会触发相关客户建议的后台刷新；生成需要一些时间，客户页会更新生成状态，首页可集中查看。资料不用一次填齐，也可以随时点“帮我想下一步”或“重新思考”。记录详情的 AI 整理区有“看这位客户的推进建议”入口。

每轮建议包含：

- **本轮目标与判断依据**：先推进哪一步，为什么优先做。
- **最多三个行动**：每项说明目的，以及建议找谁、准备材料、可用提问话术、怎样算有进展；展开后可查看细节。
- **待核实问题和推进风险**：未确认的预算、决策链、技术条件等单独列出，不当成确定事实。

点“采纳为跟进事项”只创建该客户的跟进中事项（following），不设置时间、不自动启用提醒。需要日程时再打开事项补时间并确认；重复采纳同一项不会重复添加。新的资料使旧建议过期时，界面会提示基于旧信息，并要求重新思考后再采纳。历史交流和个人观察用于辅助思考，不代表客户这次作了新承诺。

建议优先显示最值得推进的一步，并提供交流依据入口。执行后可标记“已完成、受阻、暂缓、不适用”，补充原因；这些反馈会进入下一轮思考。已采纳事项标记完成时，其活动提醒也会结束；尚未采纳的建议反馈不会凭空创建日程。

推进建议用于帮助你准备交流，仍要结合现场判断。系统不自动联系客户，不自动生成合规结论，也不因客户所属行业就断言其必须开展某项测评。

## 识别有误时怎么修正

- **字听错了**：进入语音记录，点“纠正识别文字”；展开“对照原始语音转写”，改好完整内容后点“保存并重新整理”。
- **客户归错了或“他”指代不清**：先选准确客户，再重新理解；候选列表出现时点击对应客户。姓名、电话、金额仍需你核对，系统不会凭猜测补全。
- **理解没到位**：补充漏掉的背景或承诺内容后重新理解，相关旧待确认客户草稿会失效。原分析只有尚未确认的日程子事项时，可以撤回旧 P、生成新版待办，历史内容仍可查看；已有活动提醒或手动采纳的无时间待办受保护，需逐项处理或新建后续交流。

修改当前待办的提醒时，先检查页面显示的原提醒标题和时间，选择“同步当前待办提醒”会拟出变更提案，确认后才更新；选“仅修改记录”则原提醒继续执行。**一条交流纪要关联多条活动提醒时，要逐条打开对应待办修改并确认**，系统不会把纪要的新标题覆盖到所有待办。改期会检查过去时间、截止时间和与其他日程的冲突，原任务不与自己冲突。

一次多人交流会先保留完整交流纪要；不能确定某个喜好、角色或承诺属于谁时，不强行写进某位联系人画像。没有时间的事项仍先记录，由你补充日程。

## 记录和模型边界

- 企业微信官方机器人通过 `voice.content` 提供转写文字，没有向本应用提供原始录音。应用保留首次转写和后续修正，不能取回企微原音重新识别。后台另有可选专业 ASR 入口，当前因缺少 key 尚未启用。
- 旧版本没有保存原话，迁入后台的是原提案标题，来源标记“历史提案”，不伪装成完整交流记录。
- 修改原记录后，已有 AI 分析会标记过期。重整只替换尚未确认的日程草稿；保留旧子记录和版本，不覆盖已执行或已生效的提醒。新的沟通可使用“保存并整理本次沟通”独立记录。
- AI 建议不自动确定日期。明确待办需要当前原话证据；历史沟通仅辅助理解，不当成本次新承诺。
- 模型失败时保留原记录。后台登录口令、企微凭据不发送给模型。模型会收到当前记录和已选择客户的有限背景。
- 首次独立推送测试曾返回 846607；本次核查发现 2026-09-30 19:06:09 已有真实到点提醒获得平台成功回执，数据库 notifications.sent=1。平台发送链路已验证，手机通知弹出仍需用户确认。

## 运维

```bash
sudo systemctl status personal-secretary.service
sudo systemctl restart personal-secretary.service
sudo journalctl -u personal-secretary.service -n 50 --no-pager
```

升级前先执行 `sudo systemctl stop personal-secretary.service`。将新源码包及对应的 `deploy/install_crm_release.py` 上传后，用已有环境运行 `/opt/personal-secretary/.venv/bin/python /opt/personal-secretary/deploy/install_crm_release.py`。这是已有服务的源码升级包，不能单独用于全新安装。

安装器会核对进程已完全退出，在任何文件改动前检查整个压缩包，并通过 SQLite backup API 导出数据库。源码、配置和数据库备份位于 `/opt/personal-secretary/deploy/rollback-时间/`；目录权限 700，配置和数据库权限 600。数据库路径以实际生效的 `SECRETARY_DB_PATH` 为准，默认是 `/opt/personal-secretary/data/secretary.sqlite3`。备份目录的 `databases.json` 记录原库与备份文件的对应关系；若暂存配置改变数据库位置，新旧库都会检查并备份，回滚时按映射恢复。不能只复制主库文件而遗漏 WAL 中已提交的数据。

安装成功后完成配置检查和回归，再启动原服务并验证后台、企业微信连接和本人手机通知。若安装失败，服务保持停止，先检查安装状态和备份；文件逐个替换不代表整个升级具有事务原子性，不应直接启动状态不明的源码。

后台会话有效期十二小时；服务重启后需重新登录。每个来源五分钟最多五次登录尝试，防止并发试口令。忘记口令可停服务，在服务器 Python 中调用 `secretary.web.hash_password` 生成新哈希，更新 `.env` 的 `SECRETARY_WEB_PASSWORD_HASH` 再启动；不要把密码或配置打印到日志。

## 录音、上传与专业语音识别配置

本版已提供后台“语音”和客户页“录音 / 上传语音”入口、能力状态及行业热词设置，并实现阿里云百炼 Qwen ASR 适配器。**目前没有 ASR API key，专业转写尚未启用**，页面会明确显示这一状态；可继续使用企业微信语音或手机键盘语音输入，不影响文本整理。

管理员以后直接在服务器 `/opt/personal-secretary/.env` 中填写 key，无需发送到聊天。保留其他已有配置，新增或修改下面三项：

```dotenv
DASHSCOPE_API_KEY=
SECRETARY_ASR_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
SECRETARY_ASR_MODEL=qwen3-asr-flash
```

浏览器录制的 WebM/Opus 在启用转写后需要服务器安装 `ffmpeg` 才能转换；没有该工具时可上传 WAV 或 MP3。当前尚无 ASR key，因此未开启这条转写链路，也无需现在安装转换工具。录音超过5分钟会要求拆分，不会将截掉尾部的录音作为完整转写。

`DASHSCOPE_API_KEY` 留空时禁用专业转写。填写可用 key 后重启 `personal-secretary.service`，打开后台“语音”检查能力状态，再用一段短录音验证。配置保持仅管理员和服务可读，不要输出 key 到日志。

使用时先选客户（可选），上传文件或录音，点“转写成文字”，核对公司名、人名、金额、日期后再“保存并整理”。转写完成不会直接写入客户资料或启用提醒。

- 当前内网 HTTP 地址无法使用浏览器麦克风；网页录音需要 HTTPS 和麦克风授权。ASR 配好后，HTTP 内网仍可先上传手机录音文件。外部 HTTPS 配置见下一节。
- 每次录音/上传限制 6 MB、5 分钟；支持 WAV、MP3、M4A、AAC、OGG、FLAC、WebM。浏览器生成的 WebM 需要服务器 ffmpeg 转换；未安装时可先上传 WAV 或 MP3。
- 原始音频只用于本次转写，不长期保存；失败时保留手机上的原文件，再重试或手工输入。转写准确率仍需实际验证。
- 可维护最多 100 个行业热词，每个 1–60 字；已有客户名、别名、有效联系人名会自动补充为词表。热词只是识别辅助，不保证每个专有名词都正确。
- **热词仅影响本后台接入的专业 ASR，不影响企业微信自带语音转写。** 企业微信识别有误仍按“纠正识别文字”流程处理。

## 后续自行配置外网映射

推荐映射到 HTTPS 反向代理。代理目标 `http://127.0.0.1:8765`，保留 Host，并配置：

```dotenv
SECRETARY_WEB_ORIGIN=https://你的实际域名
SECRETARY_WEB_SECURE_COOKIE=1
```

后台已支持手机布局。TLS 在反向代理终止，配置外部地址后来源校验允许该地址；重启服务生效。若代理同机且不再直接内网访问，可把 `SECRETARY_WEB_HOST` 改为 `127.0.0.1`。本次不修改公司路由器、防火墙或购买网络服务。
