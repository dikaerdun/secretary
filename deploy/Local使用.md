# Windows 本机使用

这是可持续使用的本机后台。默认地址是 `http://127.0.0.1:8765`，数据保存在 `data/local-secretary.sqlite3`，账号固定为 `local-user`。没有演示客户或模拟模型结果；退出和重启会保留资料。

在仓库目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\start-local.ps1
```

启动脚本使用已有 `.venv\Scripts\python.exe`，隐藏服务窗口并打开默认浏览器。首次启动自动生成后台口令，保存到只有当前 Windows 账号可读的 `deploy/local-access.local.json`。打开该文件，复制 `password` 字段登录。脚本和日志不会显示口令；下次启动继续使用同一口令。把文件留在本机，不要分享或提交。

也可以用 `-NoBrowser` 只启动服务。端口被占用时用 `-Port 8875`；若需要另一份数据，附加 `-Database data/another-local.sqlite3`。变更端口或数据库前先停止当前实例。启动脚本会核对已运行实例；同一数据库也有系统文件锁保护。

停止：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\stop-local.ps1
```

停止脚本优先让应用关闭后台处理与数据库，再退出。它核对 PID、解释器路径、模块和实例标识，只停止本机专用服务。数据库和口令文件继续保留。电脑重启后重新运行启动脚本即可；没有安装开机任务。

## 配置与使用范围

应用先读根目录 `.env`，再用 `.env.local` 覆盖，最后使用当前进程环境中的同名配置。原 `.env` 不会被修改；本机数据库不会沿用 `SECRETARY_DB_PATH`。本机追加密钥放在私有的 `.env.local`。支持现有 `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`，聆记的 `LISTEN_NOTE_API_KEY` / `LISTEN_NOTE_MCP_URL`，以及专业语音的 `DASHSCOPE_API_KEY` / `SECRETARY_ASR_BASE_URL` / `SECRETARY_ASR_MODEL`。

后台显示“本机模式”“企微未连接”“提醒在后台可见”。本机入口不需要企微账号或密钥，不启动企微 WebSocket，不占用机器人连接，也不会发送企微消息。已经确认的事项仍会显示在日程中；本机使用时需要打开后台查看。

登录后可以手动新建客户，输入或粘贴文字材料，也可以使用 Windows 输入法语音输入，核对文字后保存。已配置 DeepSeek 时使用真实模型整理，并需要你核对客户资料、行动和提醒。显示“已配置”仅表示找到了密钥；实际凭据、余额和网络可用性在调用时验证。模型未配置或调用失败时原文仍保留，可以补齐配置后在材料中重试；不会用模拟结果代替。

### 以一次客户交流为单位

进入“客户交流”，新建一场交流。客户、实际时间可以留空；可以直接附上自己的复盘，也可以先保存交流再追加录音。现场录音、我的复盘、后续补充分别保留原文，集中展示要点、个人判断、承诺、待补时间和下一步。

“录音与材料”仍可独立导入，不必先创建客户或交流。材料整理后，可以从交流的“关联已有材料”把它归档。客户资料变更先生成待确认草稿，不自动写入客户档案；发生时间不明确时，不使用保存时间代替。

同一交流中标题明确相同的行动会汇合、保留每份来源依据。措辞不同但实际同一件事，可以勾选后“合并所选事项”。时间、责任人、归属存在冲突时，需要先通过“核对 / 修正”更正来源。仅有复盘时，你明确承诺的自己的行动也能采纳；对客户态度的猜测及客户承诺的个人转述会作为待核对观察。

采纳只建立跟进事项。没有具体时间的先保留待补时间；有时间的提醒也需另行确认。后续录音或复盘的变化不会覆盖已经采纳或确认的事项。来源在后台处理中时先保存输入，完成后页面自动更新；编辑中的草稿保留。

### 聆记连接的实际范围

聆记按完整标题导入，成功读取后保留来源并整理。2026 年 10 月 2 日使用当前连接实际检查 MCP，只有 `note_get_summary(title)` 与 `note_get_transcript(title,cursor,limit)`，没有录音列表、搜索或完成通知接口。因此当前版本无法自动发现新录音；“自动发现新录音 → 读取全文 → 内容分类 → 待核对”的目标流程需要聆记开放列表或事件能力后才能接通。检查证据保存在 `reviews/2026-10-02-listen-note-capabilities.json`，可用 `python deploy/check_listen_note_capabilities.py` 再检查工具元数据。

未配置或读取失败会明确显示状态，可保留标题或粘贴转写文字作为材料。录音识别只有配置了真实专业 ASR 服务时才可用；未配置时使用键盘语音输入。专业转写的 WebM 格式还需要本机 ffmpeg，其他支持的格式见后台提示。

只检查本机配置（不调用外部服务）：

```powershell
.\.venv\Scripts\python.exe -m secretary.local --check
```

前台启动可用 `.\.venv\Scripts\python.exe -m secretary.local`，按 Ctrl+C 停止。该方式与脚本使用同一持久数据库和口令，但进程停止脚本只管理由启动脚本创建且身份可核对的服务。

现有离线演示仍可单独运行 `.\.venv\Scripts\python.exe -m secretary.web --demo --port 8787`，密码为 `demo-only-preview`。它使用临时数据库，页面有演示标记，关闭后资料不保留。真实本机使用请运行 `start-local.ps1`。

## 2026-10-03 重构后的使用顺序

1. **先记录。** “随口记”输入或粘贴核对后的文字；语音入口维护行业词、客户简称和联系人词。原始转写与人工校对分别保留。专业识别未配置时，可用输入法语音输入或粘贴聆记转写。
2. **归入客户交流。** 已知客户的客户交流／拜访复盘短记录自动归档，原记录与已采纳待办保持同一编号。旧短记录也能从详情归入已有交流。现场录音与事后复盘发生时间不同时，可以明确确认关联，分别保留实际时间。
3. **集中核对。** 顶部“核对”汇集客户资料、日程、短记录、录音材料和客户交流行动，支持分页、客户过滤、不采纳、稍后回看及恢复。相同依据重新整理不会把已不采纳建议重新推回来；新依据会重新要求核对。
4. **推进客户与项目。** 客户档案集中展示我的行动、等待客户／同事反馈、交流和材料。多个项目分别维护金额、金额性质、审批、销售阶段、范围、采购、决策链及联系人。历史客户金额不会自动复制到每个项目；交流和行动可明确关联项目。
5. **安排与完成。** 行动详情分别核对执行预约、截止要求、回访检查、责任人和预计用时。未说几点的截止／检查按日期展示，不编造时刻。正式安排仍需确认；日周月可切换查看。完成时保存结果，顺手接下一步，无明确时间则只创建待办。

从原行动的“这次沟通／进展”输入“改到10月13日上午10点，仍60分钟”等明确口述，再选“保存并整理本次沟通”，会拟修改原安排；确认前保留原时间。明确取消也先生成取消提案。否定、条件、多备选时间会保存原话并要求澄清。普通新沟通会保留为新交流。

手机编辑时主要操作位于可见底部区域；关闭保留当前浏览器草稿，重新打开可恢复。若后台已有更新，先显示最新内容，旧草稿由你明确恢复对照。提交发生版本冲突时原输入仍保留。草稿属于浏览器会话，已保存的原文和材料版本才是持久数据。

首页“今天值得推进什么”给出依据、应找谁、准备材料与推进标准；建议可稍后处理或标记本次不适用。已完成任务不会继续出现在未完行动和截止检查节点中；取消提醒仍保留未完成事项。

## 单位、多联系人、项目决策关系与持续画像

单位可以记录集团、子公司和部门层级，多位联系人无需重复创建单位。项目里的参与单位与联系人决策角色分别维护：同人跨项目可有不同权限，一项目可有多位审批人。个人职责、工作目标与沟通偏好属于具体联系人，项目预算与采购信息属于具体项目。

后台持续从新的已归属日常资料生成带原话依据的画像候选，确认后才更新。项目按成交缺口提出少量问题；关键联系人也有需要继续了解的资料提示，可补画像或进入项目讨论，采纳行动后另行确认时间。未配置真实模型时使用规则辅助；公开检索需独立可选配置，默认不自动联网。

完整步骤与可选检索配置见 [单位联系人与智能画像](单位联系人与智能画像.md)，网页指南增加“新版 · 单位、多位联系人、项目决策关系与智能画像”章节。本轮验证范围和浏览器连接限制见 `reviews/account-intelligence-2026-10-03/交付报告.md`，不沿用上节的历史浏览器验收作为新版图证。
